## Status: Opgelost

Dit issue is opgelost. De "Versies" stap in de applicatie-wizard is nu zichtbaar en functioneel voor alle hosting-typen, inclusief SaaS.

### Situatie voor de fix
De "Versies" stap in de applicatie-aanmaak wizard werd alleen getoond wanneer het hosting type "On-premises (self-managed)" was geselecteerd. Voor SaaS-, IaaS- en PaaS-applicaties was de stap onzichtbaar, waardoor gebruikers geen versie-informatie konden toevoegen.

### Oorzaak
In `tilburg-woo-ui/src/views/ac-forms/ac-forms-applicatie/ac-forms-applicatie.js` bevatte de functie `shouldShowVersiesStep()` een restrictieve check:
```javascript
return (applicatie?.cloudDienstverleningsmodel || '').includes('On-premises (self-managed)');
```
Dit blokkeerde de stap voor alle andere hosting-typen.

### Wijziging
`shouldShowVersiesStep()` retourneert nu altijd `true`, waardoor de Versies-stap voor alle hosting-typen zichtbaar is. Voor gehoste applicaties (SaaS) wordt automatisch een default versie aangemaakt met de melding "Voor gehoste applicaties wordt een default versie aangemaakt".

### Bewijs
Hertest uitgevoerd met geautomatiseerde browser-agent op 2026-03-01:
- Wizard gestart met SaaS als hosting type
- "Versies" stap zichtbaar in de navigatie (met blauwe punt-indicator)
- Versieformulier toont vooringevulde velden: versie "1.0.0", status "in gebruik", startdatum
- "Nieuwe versie toevoegen" knop beschikbaar
- Informatieve melding: "Voor gehoste applicaties wordt een default versie aangemaakt"
