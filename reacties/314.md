## Status: Opgelost (lokaal geverifieerd)

Dit issue is opgelost en geverifieerd op de lokale omgeving.

### Analyse

Dit issue gaat over de wizard "Koppeling publiceren" waarbij de eigen aangemaakte applicaties niet gevonden worden. De leverancier kon stap 1 niet voorbij komen omdat de eigen applicatie niet in de lijst stond.

**Root cause**: De "gebruik-koppeling" wizard (`ac-forms-gebruik/gebruik-koppeling/ac-forms-koppeling.js`) filtert applicaties op basis van "gebruik" records (afnemer). Leveranciers hebben geen gebruik-records als afnemer — zij bieden applicaties aan, zij gebruiken ze niet. Hierdoor was de allowlist leeg en verscheen "No options" in de dropdown.

Het probleem deed zich specifiek voor in de gebruik-koppeling wizard (bereikbaar via `/forms/gebruik/koppeling?type=aanbieden-koppeling`), waarnaar leveranciers werden doorverwezen via de dashboard "Koppeling toevoegen" knop. De reguliere koppeling wizard (`/forms/koppeling?type=eigen-organisatie`) werkte al correct omdat deze filtert op `organisation` parameter.

### Oplossing

De fix voegt organisatietype-detectie toe aan de gebruik-koppeling wizard. Er zijn drie wijzigingen aangebracht in `tilburg-woo-ui/src/views/ac-forms/ac-forms-gebruik/gebruik-koppeling/ac-forms-koppeling.js`:

1. **allowedModuleIdsFromGebruik effect** (regel ~300): Wacht op `fullActiveOrganisation` om het organisatietype te bepalen. Voor Leverancier/Community wordt een `'ORGANISATION_OWNED'` marker gezet in plaats van gebruik-records op te halen.

2. **Module fetch effect** (regel ~364): Wanneer de marker `'ORGANISATION_OWNED'` is, worden modules opgehaald met de `organisation` query parameter om alleen eigen modules te tonen. Voor Gemeente/Samenwerking blijft de bestaande logica (ophalen per module ID uit gebruik-records) ongewijzigd.

3. **searchModules functie** (regel ~778): Bij zoeken wordt voor Leverancier/Community de `organisation` parameter meegegeven. Voor Gemeente/Samenwerking wordt nog steeds gefilterd op de allowedSet van gebruik-records.
