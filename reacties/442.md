## Status: Opgelost

Dit issue is opgelost. De oorspronkelijke bestandsnaam wordt nu correct doorgegeven bij het uploaden van bewijsdocumenten.

### Situatie voor de fix
Wanneer een document (bijv. "Rapport webrichtlijnen 2026.docx") werd opgevoerd als bewijs bij een standaardversie, werd de bestandsnaam in het overzicht gewijzigd naar `bewijs_<standaardnaam>.docx`. De originele bestandsnaam ging verloren.

### Oorzaak
In `tilburg-woo-ui/src/views/ac-forms/ac-forms-product/components/con-form-standaarden-stage.js` ontbrak de `onChangeFileName` callback op het `LogoUploadField` component voor de "dezelfde voor alle modules" modus (representative entry). Hoewel het `LogoUploadField` component de originele bestandsnaam correct doorgeeft via `file.name`, werd deze niet opgeslagen:
- De individuele entries hadden wel `onChangeFileName` en `onFileChange` callbacks
- De representatieve entry (bij "Zelfde voor alle modules") miste deze callbacks

### Wijziging
`onChangeFileName` en `onFileChange` callbacks toegevoegd aan het representatieve `LogoUploadField` in `con-form-standaarden-stage.js`:
```javascript
onChangeFileName={(filename) => updateBewijsFilename(representativeEntry.key, filename)}
onFileChange={(file) => updateBewijsFile(representativeEntry.key, file)}
```

De `generateFilenameFromDataUrl()` functie (die `bewijs_<naam>.<ext>` genereerde) wordt nu alleen nog als fallback gebruikt voor legacy-data die geen opgeslagen bestandsnaam heeft.

### Bewijs
Code-verificatie: alle `LogoUploadField` instanties voor bewijsuploads hebben nu `onChangeFileName` callback, waardoor de originele bestandsnaam consistent wordt bewaard.
