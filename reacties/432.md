## Status: Datakwaliteit importbestanden + Code-beperking -- GEDEELTELIJK BEVESTIGD

Dit gedrag wordt veroorzaakt door een combinatie van ontbrekende data in het importbestand en een beperking in de naamgeneratie bij import.

### Verificatie-methode

1. CSV-brondata geanalyseerd (`koppeling.csv`, 33 kolommen gecontroleerd)
2. Koppeling-schema configuratie geanalyseerd (naam-property met default template)
3. API-vergelijking `naam` veld vs `@self.name` metadata
4. OpenRegister code-analyse van MetadataHydrationHandler

### Bewijs: twee verschillende naamvelden met verschillende resultaten

Het systeem heeft twee naamvelden voor koppelingen:
- `naam` (business data): bevat de waarde die bij import is gegenereerd
- `@self.name` (metadata): wordt gegenereerd door het objectNameField template

**API-bewijs van het verschil:**
```
GET /api/objects/voorzieningen/koppeling?moduleA=970cf3e9-57d2-563e-8cfe-8fab173f0438

Resultaat koppeling 1:
  naam:       "970cf3e9-57d2-563e-8cfe-8fab173f0438 →"  <- UUID
  @self.name: "Gouw Belastingen →"                      <- Correct

Resultaat koppeling 2:
  naam:       "Key2Peter → Module Documentenuitvoer"    <- Correct (handmatig)
  @self.name: "Gouw Belastingen →"                      <- Correct
```

### Kwantitatieve analyse (steekproef 200 koppelingen)

| Naamtype | Aantal | Percentage |
|----------|--------|------------|
| UUID in `naam` veld | 178 | 89,0% |
| Correcte naam in `naam` veld | 22 | 11,0% |

De 22 koppelingen met correcte namen zijn handmatig aangemaakt via de wizard of bewerkt na import.

### Root cause analyse

1. **Geen `naam` kolom in CSV** -- het importbestand `koppeling.csv` heeft 33 kolommen, GEEN daarvan is `naam`
2. **Schema default wordt toegepast** -- het `naam` property heeft een default template:
   ```
   {{ moduleA }} {{ gegevensuitwisselingRichting | map: AnaarB=→, BnaarA=←, bi-directioneel=↔ }} {{ moduleB | buitengemeentelijkVoorziening }}
   ```
3. **Import-timing probleem** -- bij CSV bulk-import wordt het default template verwerkt voordat de UUID-naar-naam resolutie plaatsvindt. De `{{ moduleA }}` placeholder wordt vervangen door de rauwe UUID-string
4. **@self.name WEL correct** -- het objectNameField template wordt verwerkt door `MetadataHydrationHandler.processTwigLikeTemplate()` die WEL `resolveRelationValue()` aanroept om UUIDs naar namen te resolven

### Inconsistentie tussen weergave-locaties

De inconsistente naamgeving op verschillende plekken komt doordat sommige UI-componenten het `naam` veld tonen (met UUID) en andere het `@self.name` veld (correct geresolved):
- Koppelingen-overzicht (Beheer): toont het `naam` veld -> UUID
- @self.name metadata: correct geresolved -> "Gouw Belastingen →"

### Conclusie

**GEDEELTELIJK DATAKWALITEIT, GEDEELTELIJK CODE-BEPERKING:**
- **Datakwaliteit (primair):** Het importbestand bevat geen `naam` kolom
- **Code-beperking:** Het property-default mechanisme bij import resolved geen relatie-UUIDs naar namen, terwijl het objectNameField dat WEL doet
- **Niet een bug:** De applicatie crasht niet en de @self.name metadata is WEL correct

### Bijkomende oorzaak: schema-afwijking moduleB

Een deel van de naamgeneratie-verwarring is veroorzaakt door een schema-afwijking (zie #433 voor volledige analyse). Op 2025-11-03 (commit `d3cd5b2`) werd `moduleB` gewijzigd van een simpele `$ref: module` naar een `oneOf: [module, element]`. Hierdoor werden zowel applicatie-UUIDs als buitengemeentelijke-voorziening-UUIDs in hetzelfde `moduleB` veld gestopt, terwijl het naam-template `{{ moduleB | buitengemeentelijkVoorziening }}` ervan uitgaat dat dit twee gescheiden velden zijn.

Dit is op 2026-03-02 gecorrigeerd: `moduleB` verwijst nu weer uitsluitend naar modules, en `buitengemeentelijkVoorziening` is weer zichtbaar als apart veld.

### Aanbeveling
1. **Data:** Voeg een `naam` kolom toe aan het importbestand met vooraf samengestelde namen
2. **Code:** Laat het property-default mechanisme dezelfde UUID-resolutie toepassen als objectNameField
3. **Workaround:** Bulk-update van alle koppeling `naam` velden met de waarde uit `@self.name`
